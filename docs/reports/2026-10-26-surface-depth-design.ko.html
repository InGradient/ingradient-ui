표면 깊이(Surface Depth) 설계안

승인됨(진행) · 2026-10-26 작성 · 기준 커밋 ecdaa1f(브랜치 fix/broken-controls) · 이 문서 작성 중 제품 코드는 바꾸지 않았다.

요약. 모서리의 위계는 토큰 값이나 이름이 아니라 무엇이 무엇 안에 있는가로 정해진다. 그래서 상자(표면) 컴포넌트가 자기 깊이를 알고, 깊이에 맞는 모서리를 쓰게 한다. 같은 장치로 배경·그림자·테두리도 정할 수 있다. 깊이 정보를 주는 Provider가 없으면 지금과 똑같이 동작하므로, Platform부터 화면 하나씩 켜고 Edge는 나중에 따로 정한다.

원인은 코드에서 확인했다.

  • 같은 역할이 다른 토큰을 쓴다. 카드·섹션 19곳이 lg(20px) 9곳, xl(24px) 8곳, 2xl(20px) 2곳.
  • 같은 토큰을 다른 역할이 쓴다. xl을 모달, 카드, 사이드바, 팝오버가 모두 쓴다.
  • 이름으로는 역할을 알 수 없다. Create Project의 바깥 상자는 이름이 Card지만 실제로는 다른 카드를 감싸는 껍데기다.
  • 같은 컴포넌트가 놓인 곳에 따라 깊이가 다르다. 대시보드 위젯은 바깥 Card(radius-xxs, 8px) 안에 BarChartCard를 넣는다. 토큰 하나로는 두 위치를 다르게 표현할 수 없다.

2. 규칙

  1. 표면은 배경·테두리·모서리를 가진 상자다. 가장 바깥 표면이 깊이 1이고, 그 안의 표면은 깊이가 하나씩 늘어난다.
  2. 떠 있는 표면(모달, 대화상자, 서랍, 팝오버, 메뉴, 토스트)은 어디서 열리든 깊이 1에서 새로 시작한다.
  3. 선으로 나누는 레이아웃 열(모서리 0인 Catalog 사이드바 같은 열)은 표면이 아니라서 깊이를 올리지 않는다. (결정 필요 3)
  4. 최대 깊이는 3이다. 깊이 4 이상은 DESIGN.md 7절의 "장식 패널을 다른 장식 패널로 감싸지 않는다"를 어긴 것으로 검사에서 실패한다.
  5. 컨트롤과 작은 요소(버튼, 입력창, 칩, 체크박스)는 깊이와 관계없이 고정값을 쓴다.
  6. 불변식: 둥근 표면 안의 둥근 표면은 모서리가 바깥보다 작다. 이 불변식을 DOM 구조 기준 검사로 만들어 CI에서 지킨다.

3. 깊이별 값(제안)

모서리 값은 시험 빌드 (다)·(라)에서 화면으로 확인했다. 배경·그림자·테두리는 아직 시험하지 않았고, 지금 쓰는 토큰을 깊이에 배정한 것이다.

깊이예모서리배경그림자테두리
1 · 떠 있음모달, 팝오버, 메뉴16pxsurface-raised지금 쓰는 floating/popover/menuborder-subtle
1 · 도킹둥근 페이지 패널16pxsurface-panel없음border-subtle
2카드, 섹션, 위젯12px부모보다 한 단계 밝게(값은 시험 필요)없음border-subtle
3카드 안 미리보기 틀, 셀8px투명 또는 surface-interactive없음없음 또는 border-subtle
컨트롤버튼, 입력창8px각 컴포넌트가 정함(변경 없음)
작은 요소칩, 체크박스6px변경 없음
알약배지, 토글999px변경 없음
  • 현재 섹션 카드(SectionPanel)는 surfacePanel 레시피를 써서 shadow-panel(0 20px 60px)을 갖는다. 깊이 2부터 그림자를 없애면 DESIGN.md의 "그림자는 패널·메뉴·팝오버·서랍·대화상자·토스트에만"과 맞는다.
  • 팝오버 그림자는 파란빛(rgba(77,136,255,.34))이다. 이것을 유지할지는 결정 5에서 정한다.
  • 깊이 3(8px)과 컨트롤(8px)이 같다. 컨트롤은 표면이 아니라서 불변식에 걸리지 않는다.

4. 구현 방식

깊이는 React context로 전달한다

모달과 팝오버는 portal로 DOM 밖에 그려져서 CSS 상속으로는 "어디 안에 있는지"가 끊긴다. React context는 portal을 넘어 이어진다. 그래서 깊이는 context로 전달하고, 화면에 쓰는 값은 CSS 변수로 둔다.

// @ingradient/ui (새 export, 이름은 안)
<SurfaceDepthProvider>          // 켜기. 없으면 지금 값 그대로(legacy)
useSurfaceDepth()               // { depth, enabled }
<SurfaceDepth float>            // 떠 있는 표면: 깊이 1에서 새로 시작
<SurfaceDepth>                  // 일반 표면: 부모 깊이 + 1

// 표면 컴포넌트가 하는 일
data-ig-depth="2"               // 검사·테스트용 표시
border-radius: var(--ig-depth-2-radius)   // 깊이별 토큰
  • Provider가 없으면 아무것도 바뀌지 않는다. 표면 컴포넌트는 지금 쓰는 토큰을 그대로 쓴다. 그래서 Edge와 외부 사용처는 영향이 없다.
  • Card는 이미 radius 속성을 받는다(기본값 var(--ig-radius-lg)). 명시한 값이 이긴다. 예외가 필요할 때 쓰되, 위계 검사에서 걸리면 이유를 남긴다.
  • 공개 API는 추가만 하므로 깨지는 변경이 아니다.

7. 결정할 것

결정 기록(2026-10-26). 1번(이 방식으로 진행)을 승인받았다. 2~7번은 따로 정하지 않아 이 문서의 제안값으로 진행한다: 모서리 16·12·8px, 모서리 0인 레이아웃 열은 깊이로 세지 않음, 모서리 먼저(배경·그림자·테두리는 시험 빌드 뒤 결정), 팝오버 그림자 유지, Edge는 4단계에서 결정, 최대 깊이 3. 각 값은 단계 진행 중에 바꿀 수 있다.
  1. 이 방식(깊이 기준)으로 진행할지.
  2. 모서리 값 16 · 12 · 8px. 시험 빌드 (다) 6054, (라) 6055에서 확인 가능(임시 서버, 아래 부록).
  3. 모서리 0인 레이아웃 열을 깊이로 셀지(규칙 3). 세지 않으면 Catalog 사이드바 안의 카드가 깊이 1(16px)이 된다.
  4. 배경·그림자·테두리를 이번 범위에 넣을지, 모서리 먼저 할지.
  5. 팝오버의 파란 그림자를 유지할지.
  6. Edge 적용 시점.
  7. 최대 깊이 3을 규칙으로 할지.
