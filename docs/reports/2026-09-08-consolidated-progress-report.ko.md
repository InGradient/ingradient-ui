# InGradient UI·Platform 통합 진행 리포트

작성일: 2026년 9월 8일  
대상: 디자인 시스템, Platform·Edge 화면, 검증 체계, 실제 Platform 연결, main 통합  
주요 기록 기간: 2026년 8월 19일~9월 8일. 6월 21일 계층 감사는 배경 자료로 참고했다.

## 1. 현재 어디까지 왔는가

**공통 디자인 기준을 정리하고, 화면을 더 쉽게 찾고 검토할 수 있게 만들었으며, 이를 실제 Platform에 연결해 주요 사용 흐름을 확인했다. 관련 작업은 두 저장소의 main에 병합하고 원격 저장소에 올렸다.**

다만 제품 전체의 검증이 끝난 것은 아니다. 최종 모바일 화면 검토에서는 하단 메뉴가 잘리는 기존 문제가 발견됐다. 운영 서버의 인증·권한과 실제 Edge 장비 연결도 이번 로컬 검증으로 확인된 범위에 포함되지 않는다.

| 영역 | 현재 결과 | 사용자와 팀에 주는 의미 |
|---|---|---|
| 공통 디자인 기준 | 색상·글자·간격 안내와 재사용 기준 정리 | 화면마다 같은 기준을 다시 정하는 부담 감소 |
| 디자인 기준 탐색 | 검색·범주 선택·복사 기능 완료 | 필요한 값을 찾아 개발 작업에 옮기기 쉬워짐 |
| 키보드 접근성 | 공통 요소 개선, Storybook 접근성 실패 40건 해소 기록 | 마우스 없이도 이미지·목록·대화상자를 조작하는 기반 개선 |
| 화면 비교 기준 | Linux 대표 화면 15개 검토·정비 | 이후 화면 변경을 비교할 기준 확보 |
| 패키지 전달 | 외부 앱 설치·빌드 검증, 공개 경로 정리 | UI 저장소 밖에서도 공통 화면을 사용할 수 있는지 확인 |
| 실제 Platform 연결 | 로컬 서버와 연결한 주요 흐름 23개 검증 통과 | 로그인부터 이미지 업로드·댓글 저장까지 실제 동작 확인 |
| 코드 통합 | UI·Platform 모두 main 병합·push 완료 | 흩어진 작업을 공통 개발 기준에 반영 |
| 모바일 완성도 | 하단 메뉴 잘림 미해결 | 모바일 작업을 마무리하려면 추가 수정 필요 |

이 문서는 기존 리포트를 종합한 기록이다. 과거 테스트를 새로 실행했다고 표시하지 않으며, 최종 병합 때의 로그와 화면 검토 결과를 구분해 사용했다. 원격 main과 로컬 커밋의 일치는 작성 시점에 다시 확인했다.

6월 감사에 나오는 모든 지적이 해결됐다는 뜻은 아니다. 이후 리포트에서 완료 근거를 확인한 항목만 아래 성과에 포함했다.

## 3. 무엇이 달라졌는가

### 3.1 화면을 만드는 공통 기준이 명확해졌다

색상·글자·간격 같은 가장 작은 기준을 바탕으로 버튼과 입력칸을 만들고, 이를 묶어 화면을 구성하는 역할을 정리했다. 화면을 제공하는 패키지와 실제 제품 앱의 책임도 구분했다.

| 구성 | 쉬운 설명 | 담당하는 일 |
|---|---|---|
| `@ingradient/ui` | 공통 화면 부품 | 색상·간격 기준, 버튼, 입력칸, 표, 공통 화면 조합 |
| `@ingradient/platform-pages` | Platform용 화면 구성 | 로그인·카탈로그·설정 등 제품 화면 표현 |
| `@ingradient/edge-pages` | Edge용 화면 구성 | 로그인·라이선스·데이터 선택·촬영 관련 화면 표현 |
| 실제 제품 앱 | 화면과 서비스 연결 | 로그인 세션, 권한, 서버 요청, 데이터 저장, 화면 이동 |

따라서 Storybook에서 화면과 버튼 반응을 확인한 결과는 실제 서버의 인증·저장 성공과 구분해서 해석해야 한다.

Edge에서는 데이터 카드, 장치 연결 설정, 촬영 설정의 제목·간격·버튼 배치를 공통 기준에 맞췄다. 촬영 버튼, 이미지 위 표시, 슬라이더처럼 기능에 필요한 고유한 표현은 유지했다. 로그인과 라이선스 화면의 입력 전·오류·연결 필요 상태도 확인했다. [자료 1·2·6]

### 3.2 디자인 기준을 찾고 복사할 수 있게 됐다

기존 토큰 안내는 목록을 읽는 데 초점이 있었고, 비슷한 안내 화면이 여러 곳에 있었다. 대표 안내 화면을 정리한 뒤 실제 작업에 필요한 탐색 기능을 추가했다.

- 토큰 이름, 용도, 현재 값으로 검색한다.
- 색상·글자·간격 등 범주로 좁혀 본다.
- 토큰 이름과 값을 함께 복사하거나, 검색 결과에서 각각 복사한다.
- 밝은 화면·어두운 화면과 정보 밀도에 따라 실제 적용되는 값을 확인한다.
- 상태 안내의 배경·테두리·글자가 함께 읽기 쉬운지 검토한다.

긴 한국어·영어 제목, 숫자와 시간, 비어 있는 카드, 긴 스크롤 목록도 예시에 추가했다. 이는 작은 화면과 실제 제품 문구에서 생기는 문제를 더 일찍 발견하기 위한 작업이다. [자료 2·3]

### 3.3 키보드 사용과 접근성이 개선됐다

| 대상 | 개선한 동작 |
|---|---|
| 표 | 행을 키보드로 선택하고 Enter·Space로 실행, 행과 열의 의미를 읽을 수 있는 이름 제공 |
| 이미지 카드 | 이미지 열기와 메뉴 버튼을 각각 독립된 조작 대상으로 분리 |
| 파일 업로드 | 키보드로 업로드 영역에 이동하고 파일 선택 실행 |
| 대화상자 | 열릴 때 초점 이동, Escape로 닫기, 닫힌 뒤 이전 초점 복원 |
| 차트 | 마우스로 찍는 데이터와 같은 정보를 키보드로 선택할 수 있는 표 제공 |
| 긴 스크롤 영역 | 키보드로 초점을 옮기고 내용 탐색 |
| 화면 이름과 구조 | 입력 이름, 제목 단계, 탐색 영역 이름 등 보조기술이 이해하는 정보 보완 |

9월 2일 리포트의 전체 Storybook 검사에서는 기존 접근성 실패가 **40건에서 0건**으로 줄었다. 그중 30건은 여러 카탈로그 화면이 공유하는 이미지 카드의 중첩 버튼 구조에서 발생했다. 공통 원인을 고쳐 여러 화면의 오류를 함께 해소했다.

당시 전체 Storybook 브라우저 검증은 213개 파일·506개 테스트를 통과했다. 이 수치는 당시 결과이며, 최종 병합 때 재실행한 단위 테스트 317개와 합산하지 않는다. [자료 1·3]

### 3.4 화면 비교와 패키지 검증이 보강됐다

화면 비교에서는 삭제된 예시와 잘못된 화면 대상을 정리했다. 존재하지 않는 Storybook 화면의 오류 페이지가 정상 기준 이미지로 받아들여지지 않도록 검사도 보완했다.

9월 8일에는 Linux 기준 화면 15개를 검토했다. Theme Lab의 오래된 참조와 Token Overview의 긴 글꼴 값 표시를 수정하고, 해당 두 화면을 실제 Linux 실행 결과로 반영했다. 나머지 13개 화면은 같은 실행에서 일치했다. macOS 캡처를 Linux 기준 이미지로 대신 사용하지 않았다.

패키지에서는 공개 경로와 타입 파일을 점검하고, 세 패키지를 저장소 밖의 별도 앱에 설치해 타입 검사와 배포용 빌드를 확인했다. 공통 코드를 공유하면서 루트 UI 패키지의 JavaScript 합계도 **1,074.1KB에서 497.1KB로 약 54% 감소**했다. 이는 UI 패키지 산출물 수치이며, Platform 전체 앱 용량이나 사용자 체감 속도의 측정값은 아니다. [자료 4]

### 3.5 실제 Platform의 주요 흐름까지 연결했다

실제 Platform에 새 UI 패키지를 연결하자 예전 가져오기 경로와 현재 공개 경로가 맞지 않아 빌드가 막혔다. 초기 소비자 연결 작업에서는 25개 TypeScript 오류가 보고됐으며, 관련 화면 요소·공통 동작의 경로와 상태 표시를 현재 기준에 맞춰 수정했다.

이어 실제 로컬 서버와 임시 데이터베이스를 사용하는 브라우저 검증을 수행했다.

| 사용 흐름 | 확인한 결과 |
|---|---|
| 계정 만들기·로그인 | 가입 정보 저장, 잘못된 비밀번호 거절, 올바른 로그인 |
| 프로젝트·데이터셋 | 생성 후 실제 저장 |
| 이미지 업로드 | 품질 선택 화면, 테스트 이미지 2개 업로드, 목록 표시 |
| 이미지 찾기 | 검색과 검색 해제, 파일 이름 역순 정렬 |
| 이미지 선택 | 전체 선택과 선택 해제 |
| 이미지 상세 | 상세 화면 표시, 확대·축소 반응 |
| 댓글 | 작성한 댓글의 저장 확인 |
| 추가 창 | 데이터셋 대화상자 표시, Escape로 닫기 |
| 모바일 기본 표시 | 메뉴와 이미지 목록의 기본 표시 확인 |

테스트는 임시 로컬 데이터와 계정을 사용했다. 운영 데이터 변경이나 운영 서버 배포를 수행한 검증은 아니다. 모바일 기본 표시 통과는 하단 도구 모음 전체의 사용 가능성을 증명하지 않으며, 최종 화면 검토에서 별도 문제가 확인됐다. [자료 5·7]

### 3.6 흩어진 작업을 main으로 통합했다

최종 통합 과정에서 Platform 원격 main에 로컬 기준보다 117개 커밋이 추가돼 있었다. 최신 폴더 구조와 구현을 유지하면서 이번 연결 변경을 맞췄고, 원격에서 삭제된 오래된 파일을 되살리지 않았다.

최신 카탈로그에서 필요한 공개 대화상자와 업로드 품질 타입을 UI 패키지에 노출했다. 데스크톱·모바일에 전달하는 화면 정보를 구분하고, 빠져 있던 파일 입력 연결을 복구해 업로드 버튼이 실제 업로드 흐름으로 이어지도록 했다.

이전에 남겨 둔 Storybook 실험 설정, 카탈로그 관련 조사 문서, 기존 E2E 테스트 이전 작업도 검토·보존해 커밋했다. 로컬 도구 설정과 임시 로그 폴더는 원격에 올리지 않고 유지했다.

| 저장소 | 최종 구현 커밋 | 전달 상태 |
|---|---|---|
| InGradient UI | [`c210de1`](https://github.com/InGradient/ingradient-ui/commit/c210de1e4b510721f54a16a6aced885d7a3d22d4) | main 병합·push 완료, 원격과 일치 |
| InGradient Platform | [`540e2f3`](https://github.com/InGradient/ingradient-platform/commit/540e2f34962cded9ddbb9dacea19d5e770df5de4) | main 병합·push 완료, 원격과 일치 |

최종 통합 시 두 저장소 모두 main에 포함되지 않은 로컬 브랜치는 없었다. 위 커밋은 이 통합 리포트 작성 전의 구현 기준이다. 소스 전달 완료와 운영 배포 완료는 별개이며, 이번 작업에서 운영 배포 완료를 확인하지 않았다. [자료 7]

| Platform 프런트엔드 | 타입 검사·배포용 빌드 통과 | 최종 병합 로그 재확인 |
| 실제 로컬 서버 브라우저 검증 | 23개 체크포인트 통과 | 최종 병합 로그 재확인 |
| 최종 화면 충실도 검토 | 통과 | 제공된 데스크톱·모바일·상세 화면 범위 |
| 최종 화면 사용성·잘림 검토 | **미통과** | 모바일 하단 메뉴 잘림 확인 |
| 원격 main 일치 | 두 저장소 일치 | 통합 리포트 작성 시 다시 조회 |

**자동 테스트는 통과했지만 최종 화면 검토는 모두 통과하지 않았다.** 모바일 자동 검사는 메뉴와 이미지 목록을 확인했으며, 하단 메뉴가 실제 화면 안에 보이고 눌리는지까지 검사하지 않았다. 두 결과는 서로 다른 범위를 확인한 것이다.

또한 예전 리포트의 “작은 화면 가로 잘림 없음”은 해당 시점·화면의 가로 방향 검사 결과다. 최신 Platform에서 발견된 세로 방향 하단 메뉴 잘림을 부정하는 근거가 되지 않는다.

## 5. 이전 리포트에서 달라진 상태

| 이전 기록 | 이번 통합 기준의 상태 |
|---|---|
| 토큰 검색·복사 기능을 다음 단계로 제안 | 9월 2일 완료 |
| Storybook 접근성 실패 40건 존재 | 기준선 복구 작업에서 해소 |
| Linux 기준 이미지 승인·정비 대기 | 9월 8일 리포트에서 15개 검토·정비 확인 |
| 실제 Platform의 UI 가져오기 경로 불일치 | 소비자 연결과 최종 병합에서 수정, 빌드 통과 |
| Platform 변경은 아직 커밋·push하지 않음 | 이후 커밋·main 병합·push 완료 |
| 초기 Platform 화면 검토 두 종류 모두 통과 | 초기 체크아웃의 기록. 최신 병합본은 모바일 잘림으로 한 검토 미통과 |
| 별도 작업 공간의 문서·설정이 미반영 | 최종 통합에서 커밋·병합, 로컬 임시 자료는 보존 |

과거 리포트는 당시 기록으로 보존한다. 현재 진행 상태를 판단할 때는 이 표와 최종 검증 범위를 함께 사용한다.

## 6. 남은 과제와 권장 순서

다음 순서는 이번에 확인된 사용자 영향과 검증 공백을 기준으로 제안한다. 아래 항목은 아직 완료한 작업이 아니다.

| 우선순위 | 과제 | 필요한 이유 | 완료 판단 기준 |
|---|---|---|---|
| 1 | 모바일 카탈로그 하단 메뉴 잘림 수정 | 보기·필터·정렬·내보내기·업로드에 접근하기 어려움 | 375×812에서 하단 메뉴가 보이고 각 동작을 실제 실행, 회귀 검사에 포함 |
| 2 | 운영 인증·권한 연결 검증 | 로컬 로그인만으로 조직·초대·라이선스를 보장할 수 없음 | 운영 또는 검증 환경에서 로그인, 조직 접근, 권한별 허용·차단 흐름 확인 |
| 3 | 이전 E2E·경계 검사 스크립트 정리 | 예전 경로와 브라우저 도구 사용법에 의존하는 검사 존재 | 현재 폴더 구조와 도구에서 검사가 실제 실행되고 검증 범위를 문서화 |
| 4 | 카탈로그 편집 검증 확대 | 도형 편집·실행 취소·클래스 연계는 이번 집중 검증 밖 | 편집→실행 취소→저장→다시 열기, 클래스와 데이터셋 연결 확인 |
| 5 | 실제 Edge 앱·장비 연결 검증 | 화면 패키지 확인과 장비·라이선스 서버 연동은 별도 | 앱에서 장비 연결, 라이선스 처리, 촬영·저장 흐름 확인 |
| 6 | Platform 초기 로딩 용량 검토 | 최종 빌드의 주 파일 약 1.24MB 경고 잔존 | 실제 로딩 측정 후 필요한 코드 분리 적용, 기능 회귀 없이 비교 |

모바일 문제의 검토상 원인은 화면 전체 높이를 사용하는 카탈로그와 상단 여백 52px을 추가하는 앱 틀이 결합된 것이다. 넘친 영역을 숨기는 설정 때문에 하단 메뉴가 화면 밖으로 밀렸다. 이번 병합의 세 파일 수정에서 새로 만든 문제는 아니며, 별도 수정 과제로 남겼다.

운영 인증·API는 이전 소비자 검증 중 HTTP 503이 기록됐다. 이 리포트 작성 시 서비스 상태를 재조회하지 않았으므로 현재도 장애라고 단정하지 않는다. Edge 실제 앱 저장소도 당시 작업 경로에서 확인되지 않아 장비 연동을 검증하지 못했다.
