1. 결론

질문답
하드코딩이 많은가?아니다. padding·margin·gap에 직접 쓴 px 값은 0건이다. 모두 var(--ig-space-*)를 거친다. 다른 속성(width·top 등)의 px도 토큰 정의 파일 밖에서는 사이드바 컨테이너 쿼리 2줄뿐이다.
그런데 왜 불규칙한가?원인이 하드코딩이 아니라 세 가지다. (a) 토큰 스케일이 4px 그리드가 아니라 2px 단위(DESIGN.md 명시), (b) 숫자 prop의 의미가 컴포넌트마다 다름, (c) 2~3px 토큰을 요소 사이 간격에 사용.
4px 그리드를 적용하려면?코드 수정이 아니라 스케일 정책 결정이 먼저다(§2). 결정 없이 값만 고치면 토큰 위계가 깨진다.

3. 숫자 prop이 px로 해석됨 (34건)

Stack·Inline의 gap은 space()를 거쳐 숫자를 px 그대로 쓴다(shared.ts:15). 그래서 gap={3}은 8px 토큰이 아니라 3px이다. 반면 GridContainer·VirtualizedImageGrid의 gap 숫자는 토큰 인덱스다(grid-container.tsx:12). 같은 이름 prop의 의미가 다르다. 렌더링 확인: Create Project 화면에서 3px 간격이 실제로 계산됨.

7. 검사 방법과 한계

  • 정규식으로 padding·margin·gap(+방향별)과 gap={n}/padding={n} JSX prop을 추출해 토큰 값으로 환산했다. 스크립트: /tmp/spacing-audit/scan.mjs(저장소에는 넣지 않음).
  • 한계: top·left·width·height, 중첩 calc(), 변수에 담았다가 쓰는 값, 스타일 객체의 동적 값은 이 검사에서 제외했다. 브라우저 계산값은 Create Project와 Breadcrumbs 두 화면만 직접 확인했다.
  • Storybook 링크는 파일 → 대표 화면 매핑(근사)이다. 해당 줄이 실제로 보이는 상태는 화면에서 찾아야 한다.
  • 이 리포트는 Omarchy에서 제공하며 Tailscale 안에서만 열린다.
